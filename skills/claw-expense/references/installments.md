# 分期账单

每次调用都使用 `bash "{baseDir}/scripts/run.sh" --db <用户账本> --json ...`。首次先检查 `installment --help`；不支持时说明需要升级 CLI，不丢失分期信息后声称已记好，也不自行升级。所有金额使用十进制字符串，不用浮点计算。

## 建立计划

确认用户提供的是总本金、期数、首期日期、实际消费日期，以及是否免手续费；`fee` 表示总手续费，不是每期手续费或利率。手续费不明确时澄清，不估算或当作零。支持人民币按月 2–360 期；等本金、等手续费均分，各自尾差放最后一期。其他还款方式需要先说明当前限制。

优先 `installment record --request-id <来源消息ID-操作序号>`，通过 stdin 传 JSON：

```json
{"amount":"1000.01","fee":"1.01","periods":3,"date":"2026-01-20","first_due_date":"2026-01-31","category":"购物","merchant":"手机商店","channel":"信用卡"}
```

可加 `occurred_at` 表示原消费实际时间，保留已知偏移和精度，与 `date` 保持一致。日期依据用户时区解释并固定，不依赖执行机器今天。自定义分类需先创建支出分类。

计划本身不计入已发生的收支，也不额外记一笔总支出。返回的 `plan.id` 用于后续操作；保留完整请求及 ID 以便重试。上例前两期各 333.66 元，最后一期 333.70 元，总计 1001.02 元；金额以 CLI 返回为准。

## 查询与确认

- `installment show <分期ID>` 查看完整排期、剩余期数/金额及当前关联账单。
- `installment list` 默认仅进行中，`--status all` 查所有；日期筛选是原消费日期。
- `installment due --as-of YYYY-MM-DD` 查截至该日所有到期未确认期数，按应还日筛选；提醒时不要限定当月，以免漏掉跨月逾期。注意分页，读取到 `total` 全部记录为止。
- `installment confirm <分期ID> --period 1 --date YYYY-MM-DD --request-id <稳定标识>`：仅在用户确认实际扣款后执行。可用 `--occurred-at <带偏移的时间>` 记录扣款时间。本期本金与手续费合计生成一笔支出，归实际扣款日；应还日保留不变。提前扣款可早于应还日，不能早于原消费日。
- `summary` / 普通 `list` 只包含已确认支出。未确认期数需另行查询计划，不把计划剩余金额当作已发生支出或银行账户余额。

同一请求标识和载荷返回首次结果快照，`replayed: true` 时不能再次写入；当前状态用 `installment show` 查询。`IDEMPOTENCY_CONFLICT` 必须核对载荷，不能换标识盲目重试。即使未传标识，同一期同日期/时间重复确认也只关联同一支出；不同日期/时间报 `ALREADY_CONFIRMED`。

## 纠错与取消

确认后用返回的 `transaction.id` 退款、修改或作废，沿用主 Skill 的用户意图与稳定请求标识规则。普通 `show <账单ID>` 可查分期关联。退款、金额纠错或作废不重开分期期数；`schedule` 保留原确认事实，`transactions` 展示当前账单，避免重新确认导致重复记账。

`installment cancel <分期ID> --request-id <稳定标识>` 只取消全部剩余未确认期数，保留已确认支出、退款与历史，不代表已向银行取消还款。应先确认用户确实要取消剩余排期，不能把商家退款或提前还款直接当作取消。已全部确认计划不能取消。

计划不支持直接编辑；填错时按用户意图取消并重建。部分确认后只能对剩余本金和手续费建新计划，不能再录一遍原总额。`installment history <分期ID>` 查创建、确认、取消审计。

## 提醒

到期清单只读；CLI 没有后台调度，建立计划不会自动发提醒。用户要求自动提醒时，在实际执行 OpenClaw 的主机使用指定账本绝对路径、用户时区和已授权渠道，复用现有同类定时任务；查询完整的 `installment due` 分页，有到期项才汇总期数、商户、应还日和金额，请用户确认实际扣款。不能因“到期”就自动确认入账。
