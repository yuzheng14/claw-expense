# 外币消费与人民币确认

所有下文命令均使用 `bash "{baseDir}/scripts/run.sh" --db "<实际账本绝对路径>" --json` 作为入口。先按 SKILL.md 检查 CLI 是否支持 `pending`。不要将外币金额传给人民币 `add` / `record`。

## 消费时记录

使用 `pending record --request-id <来源消息ID及操作序号>`，从 stdin 传入 JSON，原币金额必须是字符串，消费日期必须显式给出：

```json
{"currency":"JPY","amount":"10000","date":"2026-09-30","merchant":"乐天","category":"购物","channel":"招行信用卡","note":"海淘"}
```

- 支持 USD、EUR、GBP、HKD、SGD、AUD、CAD、CHF、NZD、TWD（最多两位小数），JPY、KRW（仅整数）；新台币（通常简称台币）使用 `TWD`，例如 `{"currency":"TWD","amount":"1234.56","date":"2026-09-24"}`。未支持的币种应如实说明，不猜测精度或转换金额。
- JPY、KRW 的输入不能带小数点，`1000.0` / `1000.00` 也会被拒绝。始终向 CLI 传原币金额字符串，例如 `"1000"`；CLI 在内部将所有币种统一乘 100 存为整数，并校验这两种币的存储值为 100 的倍数。不要在 Skill 中预先乘 100；列表与业务 JSON 仍返回原币金额，只有原始归档中的 `amount_minor` 是缩放后的整数。
- 记录处于 `pending` 状态，返回 `pending.id`。`pending.amount` 始终是原币金额；`transaction: null` 表示没有人民币支出，不是零元支出。
- 知道消费时间时，JSON 可追加 `occurred_at`（如 `2026-09-30T14:35+08:00`）；遵循 SKILL.md 的时区和精度规则，`date` 仍必填且与时间当地日期一致。只知道日期时省略时间，不伪造凌晨零点。确认人民币金额会复制原消费时间，不改为确认时刻。
- 默认 `remind_on` 为消费日后 3 个日历日。这只是 CLI 的查询条件，不表示已建立主动提醒。
- 查询用 `pending list`，默认只列待确认，按消费日期由旧到新。支持月份、日期范围、币种、分类、搜索和分页；不要用第一页代表全部记录。
- `pending show <ID>` 看详情；`pending list --status all` 也可看已确认和取消记录。

## 确认或取消

用户给出银行实际人民币金额后，找到对应待确认记录；有多笔合理候选时询问，不猜测。

```bash
bash "{baseDir}/scripts/run.sh" --db "<账本绝对路径>" --json \
  pending confirm <待确认ID> --amount 510.38 --posted-date 2026-10-03 \
  --request-id <确认消息ID及操作序号>
```

`--amount` 是实际人民币金额，不是汇率。不知道银行准确入账日期时省略 `--posted-date`；系统确认时间由 CLI 自动记录，不能将今天冒充银行入账日，也不能把 `confirmed_at` 当作消费时间。

确认是原消费的后续动作，不要另外执行 `add expense`。返回唯一关联的 `transaction.id`，消费仍归原消费日期；跨月确认会补齐原消费月报。相同确认重复执行不生成第二笔支出；`ALREADY_CONFIRMED` 表示金额或银行入账日期与首次确认冲突，先查询，不换 ID 新建。

`--request-id` 重放返回的是原操作快照（包括当时的金额和状态）；查询最新结果用 `pending show` / `show`。确认后金额纠错、退款、作废操作使用返回的人民币 `transaction.id`；退款可超过原人民币支出。原币信息继续保留。

用户明确取消未扣款交易时，使用 `pending cancel <ID> --request-id ...`，保留历史。已确认消费不能用取消待办代替退款或作废。记录原币信息有误时，未确认记录可在用户授权下取消并重新记录；不要直接改 SQLite。

用户要求延后提醒时，按用户时区将“过两天”等转为明确日期，执行：

```bash
bash "{baseDir}/scripts/run.sh" --db "<账本绝对路径>" --json \
  pending snooze <待确认ID> --until 2026-10-05 --request-id <来源标识>
```

到指定日期当天重新进入提醒清单。`pending history <ID>` 可查创建、确认、取消和延后提醒的审计记录。

## 配置 OpenClaw 主动提醒

仅在用户要求设置提醒时创建或修改定时任务。先确定实际执行 CLI 的主机、账本绝对路径、用户时区、提醒时间和接收渠道。Skill 位于 Gateway，但命令在 Linux 沙箱执行时不能运行当前 macOS ARM64 二进制；应说明执行环境不匹配，不能自动关闭沙箱。

使用目标 OpenClaw 当前支持的定时任务工具或 CLI（先查其帮助）。按“账本路径 + 接收渠道”识别已有任务，优先复用，不在每次记录消费时新建任务。建议每天 18:00 合并检查一次，采用用户确认的时区；Gateway 需要运行、执行环境需要能读写指定账本。未确认任务创建成功前，不能承诺已开启提醒。

定时任务可能运行于不继承当前聊天的隔离会话。创建时必须在任务配置和指令中固化执行主机或 node、Skill 的实际路径、账本绝对路径、用户时区以及接收渠道/账户/对象；不要只写“按之前约定”。执行权限或主机路由不可用时停止并报告，不改用另一台机器的同名路径。参见 [OpenClaw 执行模型](https://docs.openclaw.ai/automation/cron-jobs/payloads)。

将以下任务内容中的所有占位符替换为已确认的实际值，作为自包含的定时任务指令；时区同时用于调度和计算 `--as-of`：

> 执行目标为 `<实际主机或node>`，只使用该机器上的 `<Skill绝对路径>/scripts/run.sh`，账本固定为 `<账本绝对路径>`，时区为 `<IANA时区，例如Asia/Shanghai>`；结果交付到 `<渠道/账户/接收对象>`。读取该 Skill，按指定时区确定今天 YYYY-MM-DD，通过包装脚本及 `--db` 执行 `--json pending due --as-of YYYY-MM-DD`。不要按当月筛选，否则会漏掉跨月未确认消费。按照 total 完成分页查询。若 ok 为 true 且 total 为 0，则不发送提醒。否则合并发送原币金额/币种、商户、消费日期、待确认 ID，请用户核对银行实际人民币金额。不要猜测银行已入账、不要查市场汇率代替实际金额、不要自动确认或取消。读取失败必须报告检查失败，不能解释成没有待办。

`pending due` 是只读查询：它不标记“已送达”，也不会自动延后下次提醒。定时任务负责每天合并发送一次；未确认且未延后的记录会继续出现。确认/取消后的记录自动从到期清单排除。创建后检查目标 OpenClaw 的任务列表或任务详情，并向用户报告实际建立的时间、时区及渠道；不要运行会发送真实消息的测试，除非用户授权。
